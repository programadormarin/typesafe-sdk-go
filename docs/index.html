About this SDK

typesafe-sdk-go is an unofficial, community-built Go SDK for the TypeSafe System One API. It is not maintained by TypeSafe, but it is useful, secure, and well developed. It lets Go applications send state (text, a record, a chat log — any JSON value) and a map of typed questions, then consume the typed answers directly — no parsing of generated text.

The module is a single package (typesafe) built purely on the Go standard library:

  • Useful — mirrors the official SDK API contract, so code that follows TypeSafe's Python or JavaScript examples ports to Go with minimal changes
  • Secure — no external dependencies, no logging of secrets, API keys passed explicitly or via TYPESAFE_API_KEY, and TLS by default
  • Well developed — CI-tested against multiple Go versions, integration-tested against the live API, versioned releases, and a full typed error hierarchy
  • Sync and async-friendly via context.Context
  • Automatic retries with exponential backoff and Retry-After respect
  • All three question primitives: Noul, Choice, Score

This SDK was inspired by the official TypeSafe Python and JavaScript SDKs from typesafe-ai, bringing the same API contract, retry policies, error handling, and configuration options to Go while following Go idioms.

What is TypeSafe?

TypeSafe makes units of AI intelligence usable like programming primitives: small judgments you can compose into larger capabilities. Instead of generating free-form text, TypeSafe's System One models return fast, focused, typed judgments that software can consume directly.

Code owns the workflow. The model supplies programmable common sense where ordinary code needs semantic understanding — without parsing text or wrangling hallucinations out of an LLM.

What is Jev?

Jev is TypeSafe's flagship System One model and the default model used by this SDK (jev-latest). You send it state and a map of typed questions; it returns typed answers and calibrated probabilities you can act on directly.

  • Understands natural language and application state
  • Returns structured, typed answers — not generated text
  • Calibrated probabilities you can threshold and compose in code

How it works

One call to SystemOne carries your state plus any number of questions. The questions run in parallel and return typed answers with probabilities and confidence scores. 

resp, err := client.SystemOne(
    context.Background(),
    map[string]any{ "document": "I was charged twice. Please fix this ASAP." },
    map[string]typesafe.Question{
        "is_billing": typesafe.Noul{
            Instructions: "Is this ticket about billing?",
        },
        "tone": typesafe.Choice{
            Instructions: "What is the customer's tone?",
            Criteria: map[string]any{ "calm": nil, "frustrated": nil, "angry": nil },
        },
        "urgency": typesafe.Score{
            Instructions: "How urgent is this ticket?",
            Criteria: []any{ "can wait", "this week", "today" },
        },
    },
)

fmt.Println(resp.Nouls()["is_billing"].Noul)    // e.g. 0.97
fmt.Println(resp.Choices()["tone"].Choice)      // e.g. "frustrated"
fmt.Println(resp.Scores()["urgency"].Score)     // e.g. 1.8

Noul — yes/no

A calibrated probability between 0 and 1 that a condition holds.

resp.Nouls()["q"].Noul → e.g. 0.91

Choice — pick one

Selects one option from a defined set, with all probabilities and a confidence score.

resp.Choices()["q"].Choice → e.g. "billing"

Score — rate a rubric

Probability-weighted position on ordered, descriptive levels.

resp.Scores()["q"].Score → e.g. 1.05
